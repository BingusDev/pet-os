## AlicePET OS v0.1 (alicepet) — 2026-11-16

- Built the first real app in `alicepet/` from `sdk/Template`: BOOT (P.E.T., 2s progress, Navi line), NAVI HOME (status bar, Alice, speech bubble, key footer), CHIP FOLDER (7-chip carousel, `n/7`, glow on selected), BATTLE CHIP IN! (slotted, "Coming soon", Alice line), ESC sleep overlay.
- Architecture: `model/chip_registry` (chip table, sprites), `viewmodel/alice_viewmodel` (LVGL-free state machine), `view/alice_view` (LVGL). The reactive layer and template screens/widgets were removed.
- Desktop: `cmake --preset darwin-arm64 && cmake --build --preset darwin-arm64-rel`, then run `build/darwin-arm64/Release/alicepet`.
- Snapshot mode: `ALICEPET_SNAPSHOT=<dir> build/darwin-arm64/Release/alicepet` writes boot/home/folder/folder-next/slotted at 320x170, plus `@3x` copies made by a PIL script kept outside the repo (`/tmp/alicepet-tools/scale3x.py`, run with `/usr/bin/python3`; the user site with PIL is not visible under `-I`).
- Device: `bin/build-device.sh .../alicepet` builds on grandworld-pi; output `pet-build/alicepet/build/cp0-cross/Release/alicepet` is ARM aarch64 ELF.
- Known gaps: no icon yet; app-builder.json author/source_repo/share_code/categories/icon left as TODO; middle-dot and element glyphs unsupported by bundled Montserrat, so ASCII separators are used; slotted chip not rotated (-8 deg); title glow is a rounded box with shadow, not a true text glow; config/template-app.conf and the desktop frame's dark-mode binding are leftovers from the template and not used by AlicePET.
- 2026-11-17 chip art: folder/slotted chips are PNGs in `alicepet/assets/images/chips/` rendered from `mockups/chips.html` by headless Chrome (big 0.58x, small 0.42x, tilt -8deg, Arial Black titles, check/bolt icons). Regenerate: `zsh /tmp/alicepet-tools/render.sh` (scripts are outside the repo). Slotted status lines are placeholders (`kSlotCopy` in alice_view.cpp). `ALICEPET_SNAPSHOT_ALL_CHIPS=1` adds `chips/folder-NN.png` + `chips/slotted-NN.png` to snapshot mode.

## AlicePET OS v0.4 (2026-11-17): packaging, Talk to Alice, NET SCAN

- **Packaging:** `bin/build-device.sh alicepet --package` builds on grandworld-pi, runs CPack (`cp0-cross-deb`), lists the .deb and copies it to `alicepet/dist/AlicePET_<ver>_rev1_arm64.deb`. The package contains `/usr/bin/alicepet`, `/usr/share/alicepet/{fonts,images/chips,audio}`, the 48x48 launcher icon `/usr/share/APPLaunch/share/images/alicepet.png`, the APPLaunch entry `/usr/share/APPLaunch/applications/alicepet.desktop` and the conffile `/etc/alicepet.conf`. No systemd unit (APPLaunch launches it). Package identity vars in `cmake/cm0-package.cmake` are FORCEd because the Pi's build cache still held "TemplateApp". `alicepet/deploy.sh` now matches `dist/AlicePET_*_arm64.deb`; `SKIP_BUILD=1 INSTALL=1 REMOTE_USER=.. REMOTE_HOST=.. ./deploy.sh` copies and `dpkg -i`s it.
- **Config:** `/etc/alicepet.conf` (repo: `alicepet/config/alicepet.conf`; `ALICEPET_CONFIG=` overrides). `[bridge] url/token/timeout_s`, `[netscan] timeout_ms` + `host=Name|address|tcp:<port>|ps5`.
- **Talk to Alice:** on Home, typing edits the prompt (digits 1/2/3 are hotkeys only while the prompt is empty), Backspace deletes, ESC clears (ESC on an empty prompt still sleeps), ENTER sends. The bubble shows "thinking..." then the reply, word-wrapped to 24x4 and paged with up/down (tag "1/9 ↓"). Emoji and typography the font lacks are stripped/mapped. Transport: `POST <url>/api/pet/ask` (cardputer-pet-terminal bridge protocol, Bearer token) on a detached worker thread (`src/app/pet_services.cpp`, `src/platform/net.cpp`, plain POSIX sockets, http:// only). Push-to-talk hook: long-press SPACE -> `Key::PushToTalk` (shows "Voice isn't wired up yet"); `ChatClient::voice_supported()` is the stub.
- **Bridge:** `bin/alicepet-bridge.sh` starts `cardputer-pet-terminal/bridge/server.mjs` with OPENCLAW_SESSION_KEY forced to `agent:main:pet` (session created with delivery "none"; verified no Telegram sends during tests). That project's `.env` still points OPENCLAW_SESSION_KEY at Holden's Telegram DM session and has an EMPTY PET_BRIDGE_TOKEN, so do not use its `scripts/run-bridge.sh` for the PET. The launcher binds 127.0.0.1 by default (`bin/bind-host.mjs` preload) and refuses any other BIND_HOST without a token.
- **NET SCAN:** [2] from Home. Hosts probed in parallel worker threads (TCP connect; a refused connect also counts as up). PS5 uses PlayStation discovery on UDP 9302: `620 Server Standby` = REST (yellow), `200` = OK. Counter counts OK + REST. Keys: up/down (or F/X), ENTER details, R rescan, ESC home.
- **Device input:** `src/platform/linux_input.cpp` now maps letters/digits/punctuation (with Shift), Enter, Backspace, Space and arrows from evdev. Untested on hardware: the real keyboard driver's Fn layer and codes still need checking.
- **Snapshots:** `ALICEPET_SNAPSHOT=<dir> ALICEPET_SNAPSHOT_CHAT="hello" ALICEPET_SNAPSHOT_NETSCAN=1 ALICEPET_CONFIG=<conf> build/darwin-arm64/Release/alicepet` also captures home-typing/thinking/reply(+pages) and netscan(-scanning/-details) using the real network.
